# One series folder across multiple sources

Downloading Overgeared from MangaDex and Asura now uses one `Overgeared` directory. SQLite permits several source/series identities to map to that directory, and the portable `.bear-cave-series.json` marker retains all identities. Schema version 3 preserves existing mappings and creates a SQLite-consistent `.pre-v3.bak` before migration.

Matching uses the full recorded series title, ignoring case and extra whitespace. It does not compare sanitized filenames, perform fuzzy matching, or combine different IDs from the same source. For example, `Name?` and `Name*` remain distinct even though Windows filename sanitization collides. Different translated titles are not automatically linked. Identical titles on different sources are treated as the same work; editions that share an identical title across sources cannot be distinguished without additional source metadata.

At startup, before the queue starts, existing identity-marked folders with matching titles across sources are consolidated into the shorter existing folder name (normally the original unsuffixed folder). Completed and staged outputs are moved without overwriting destination files. Conflicts receive deterministic import suffixes. Original secondary metadata, covers and markers are retained under `.bear-cave/imports` when a primary copy already exists. Original source/chapter IDs are preserved; recorded output, staging-folder, replacement and backup paths are updated. Only empty leftover directories are removed, without recursive deletion. Older unmarked folders are adopted only when recorded output paths prove that all recorded chapters in that folder belong to one source/series identity. Unknown folders without that provenance remain untouched.

Every planned file move is recorded in SQLite before execution. If interrupted, startup resumes that plan. A changed destination, inaccessible file, junction or unexpected path stops consolidation and leaves downloads paused; details are in the local log. Files already moved remain available, and restarting retries the recorded plan. No running chapter jobs are moved. Installing this update does not modify the running app's library; consolidation starts after a normal tray Quit and launch of the updated app.

Existing queued secondary-source series are linked before the queue resumes. Redundant normal queued chapters are cancelled with an explanatory message if a verified equivalent already exists or an earlier equivalent is queued. Explicit replacement/copy jobs are retained. Follow checks use the same reconciliation rules.

For new selections, existing verified downloads or active jobs from a linked source are skipped by normalized numeric chapter number and language, with compatible volumes (equal when both sources provide one). `001` and `1.0` match. Different languages and different known volumes remain distinct. Damaged/missing chapters do not block fetching a usable copy from another source. Nonnumeric chapter labels are kept distinct. If a source omits volumes and restarts numbering, chapter correspondence may be ambiguous. Same-source translation selection and confirmation behavior is retained.

Chapter status shows which source supplied an existing download. Verify and Re-download operate on that original source record. Queue/history records retain their source identities. Existing overlapping downloaded files are preserved rather than deleted, so an already duplicated chapter can have two files in the shared directory; new supplementary selections avoid those duplicates by default.

Shared metadata is written serially per folder. The primary `source`, cover and date_added are retained. A `sources` array records each source's URL, series ID, cover reference, metadata and known chapter total. Download counts combine source overlap; intentionally chosen same-source translations remain distinct. Startup metadata refresh uses stored records without requiring network access. Missing cover/metadata retrieval continues to be independent of chapter output.

Regression coverage in tests/cross-source.test.ts includes new shared mappings, same-source editions, sanitized-name collisions, folder and CBZ consolidation, file conflicts, metadata provenance/counts, interrupted merge recovery after reopening SQLite, junction rejection, active-job protection, queued-source linking, chapter deduplication across languages/volumes, and authenticated HTTP preview/status/follow behavior.

Verification: 120 automated tests across 14 files pass, including 11 shared-series regressions. Typechecking, formatting, production build, whitespace checks and native Electron desktop/mobile checks pass. The final packaged archive was inspected for startup consolidation, schema v3 migration and source-aware chapter manifests.
